# Status: draft (pending @tork approve linkedin)

Your AI feature backlog has 40 items. Governance is item 38, somewhere between "dark mode" and "maybe add a mascot."

This is the order that gets companies sued.

Samsung engineers pasted proprietary source code into ChatGPT — the company banned the tool within weeks, but the data was already gone. Air Canada's AI assistant invented a bereavement discount that a tribunal forced them to honour. A New York law firm submitted fabricated case citations generated by AI. Lawyers were sanctioned.

These were not careless teams. These were capable organisations that deployed AI without governance and assumed they would "add it later."

Later does not arrive until after the incident.

Three capabilities are non-negotiable before you go live:

→ PII detection in the request path — not a batch job overnight
→ Audit receipts — structured, immutable records, not log files
→ Policy enforcement in code — not system prompt suggestions the model might ignore

Adding governance after launch is not twice as hard. It is an order of magnitude harder. Your database already has months of unscanned conversations. Some contain PII. You do not know which ones.

Build governance into the foundation. Then build features on top of a system you can trust.
